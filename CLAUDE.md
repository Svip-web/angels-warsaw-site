# Angel's Warsaw

Этот проект содержит главную страницу и меню Angel's Karaoke & Lounge Bar.
Рабочий результат находится в папке `dist`. Проект использует HTML, CSS и
обычный JavaScript. Сборка и установка зависимостей для просмотра не требуются.

## Файлы проекта

| Файл | Содержимое |
| --- | --- |
| `dist/index.html` | Главная страница, разделы и форма бронирования |
| `dist/menu.html` | Страница меню и навигация |
| `dist/menu-data.js` | Позиции меню, цены, фото и видео |
| `dist/menu-page.js` | Создание карточек, раскрытие категорий и видео |
| `dist/i18n.js` | Переводы интерфейса на русский, польский и английский |
| `dist/styles.css` | Оформление и адаптивность обеих страниц |
| `dist/app.js` | Навигация, анимация первого экрана и видео главной |
| `dist/booking.js` | Отправка заявки в существующий API бронирования |
| `dist/assets/` | Публичные изображения и видео |
| `serve.mjs` | Локальный сервер с поддержкой диапазонов для видео |
| `scripts/check-site.mjs` | Проверка меню, синтаксиса и медиафайлов |
| `scripts/package-site.ps1` | Создание ZIP для сайта и Claude |
| `PUBLISHING-GUIDE-ru.md` | Подключение аккаунтов и публикации на home.pl |

## Редактирование меню

В `dist/menu-data.js` объект присваивается `window.ANGELS_MENU`.
Бар находится в `bar.groups`, кухня в `kitchen.groups`.
Внутри каждой группы есть `subgroups`, внутри подгруппы — `items`.
Кальяны находятся непосредственно в `hookah.items`.

Названия позиций сохраняй на английском, как в исходном Excel.
Заголовки разделов и кнопки переводятся на RU, PL и EN.
Для нового заголовка добавь перевод в словарь `copy` в `dist/i18n.js`.
Цены хранятся числами в PLN. Форматирование и знак zł добавляет интерфейс.

Пример позиции с одним вариантом цены

```json
{
  "name": "Название из подтвержденного меню",
  "description": "Подтвержденное описание",
  "image": "assets/имя-файла.webp",
  "prices": [{ "value": 80 }]
}
```

Пример позиции с несколькими вариантами цены

```json
{
  "name": "Название из подтвержденного меню",
  "prices": [
    { "label": "40 мл", "value": 40 },
    { "label": "Бутылка 0,7 л", "value": 700 }
  ]
}
```

Поля `description`, `image` и `video` необязательны.
Для позиции без фото существующая логика создаёт фирменную заглушку.
Для видео укажи `video` с путём к MP4 и `image` с постером.
Кальяны Shef Ice Cube и Shef Clase Azul используют подготовленные
беззвучные MP4 H.264 размером 720 × 900, в цикле.
Они воспроизводятся при появлении карточки в поле зрения.
При экономии трафика или уменьшении движения доступны ручные элементы управления.

Новые позиции добавляй по предоставленным названиям, ценам и разделам.
Если этих данных нет, запроси их у владельца.
По правке от 16 ноября 2026 года красная и чёрная икра удалены из меню.

## Локальная проверка

Запусти в корне проекта

```sh
npm start
```

Открой `http://127.0.0.1:4173/` и `http://127.0.0.1:4173/menu.html`.
Для просмотра переводов используй `?lang=ru`, `?lang=pl` и `?lang=en`.
Для кальянов открой `http://127.0.0.1:4173/menu.html#hookah`.
На мобильном в меню должны оставаться две карточки в ряд.
Проверь ширины 360, 390, 768 и 1440 px, длинные названия, цены,
быструю навигацию по разделам и открытие формы бронирования.
Проверь запуск, паузу вне экрана и повторное воспроизведение видео.

После изменений выполни проверку проекта

```sh
npm run check
```

Перед упаковкой или публикацией запусти `npm run prepare:site`.
Он обновит параметры версий CSS и JS по содержимому файлов.
Команда `npm run package` выполняет эту подготовку и проверку автоматически,
затем создаёт ZIP в папке `releases`. Для неё нужен PowerShell 7.
Claude Desktop использует `.claude/launch.json` для запуска просмотра.

Изменения сначала проверяются локально. Публикация и доступ к GitHub
выполняются по указанию владельца.
Существующая публикация использует ветку `main` и GitHub Actions.
Подготовленный сценарий home.pl включается переменной репозитория
`HOMEPL_PUBLISH_ENABLED=true` после заполнения доступа и каталога.
Точный порядок подключения описан в `PUBLISHING-GUIDE-ru.md`.
Файлы для любого статического хостинга — содержимое `dist`.
Для будущего нового домена нужно проверить HTTPS и добавить точный
origin в список разрешённых адресов отдельного API бронирования.

Секреты API находятся в отдельном серверном проекте.
Любые публичные файлы из `dist` доступны посетителям сайта.
