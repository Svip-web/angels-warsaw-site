4 Редактирование меню

Для добавления позиции передайте Claude название, раздел, цену в zł, фотографию и подтверждённое описание, если оно нужно. Можно описать задачу обычными словами. Claude должен сам найти и изменить данные, а затем показать результат.

Где хранятся данные

В dist/menu-data.js объект window.ANGELS_MENU содержит bar.groups и kitchen.groups. В каждой группе есть key, title и subgroups; позиции лежат в subgroups[].items. Кальяны находятся непосредственно в hookah.items. Ключи существующих групп используются для адресов и навигации: сохраняйте их при изменении подписей.

{
  "name": "Salmon Tartare",
  "image": "assets/kitchen-salmon-tartare.webp",
  "prices": [{ "value": 120 }]
}

Это реальный пример текущей позиции. name — название для гостя, image — путь относительно dist, value — число в PLN. Знак zł и форматирование добавляются автоматически. Поля image, video и description необязательны; без фото сайт показывает фирменную заглушку.

Как выполнять типовые правки

• Изменение цены: найдите точное название и конкретный вариант порции. Меняйте число value, а не текст в HTML. У одной позиции может быть несколько цен.
• Удаление: удалите только согласованную позицию из items. Если раздел опустел, проверьте его отображение и навигацию. Не удаляйте похожие позиции без уточнения.
• Замена: обновите название, цену и фото вместе. Проверьте, что старое название не осталось второй карточкой. Для замены брауни это уже сделано.
• Новый раздел: используйте уникальный стабильный key, добавьте title и перевод заголовка в i18n.js. Проверьте новую ссылку в закреплённой навигации.
• Описание, вес и объём: добавляйте только подтверждённые значения. Не угадывайте граммовку по фотографии.

Несколько вариантов цены

"prices": [
  { "label": "40 мл", "value": 40 },
  { "label": "бутылка 0,7 л", "value": 700 }
]

Последний фрагмент — пример структуры, а не новая правка цен. Для новой подписи label добавьте переводы и проверьте её переносы на телефоне. Названия товаров сохраняются на английском во всех трёх языках интерфейса.

Как готовить новые фото

• Преобразуйте подходящие фотографии в WebP. Для новых блюд используется размер 1000 × 800 px, соотношение 5:4. Кадрирование подбирается по блюду, чтобы сохранить тарелку и главный объект.
• Сохраняйте исходники отдельно. Публичный файл назовите понятным латинским именем без пробелов и укажите assets/имя.webp в меню.
• Сохраняйте одинаковые пропорции карточек. Проверяйте реальное изображение на телефоне: автоматическая обрезка по центру подходит не каждому исходнику.
• При замене уже опубликованного изображения используйте новое имя файла или корректное версионирование, чтобы гости не видели старую копию из кеша.

Ролики кальянов

Shef Ice Cube использует hookah-ice-cube.mp4. Shef Clase Azul использует hookah-clase-azul-v2.mp4 и постер hookah-clase-azul-v2-poster.webp. Azul длится примерно 10,17 секунды; фрагмент выбран из IMG_1346.MP4. Исходник Cube — IMG_7134.MOV.

Формат подготовленных роликов: MP4 H.264, 720 × 900 px, без звука, с постером. Видео запускается при появлении карточки, повторяется и приостанавливается вне экрана. При экономии трафика или уменьшении движения возможны ручные элементы управления. Не меняйте эту логику ради замены файла. Просмотрите полный цикл и переход с конца в начало.


6 Переводы и главная страница

Что переводится

Интерфейс работает на русском, польском и английском. Переводятся разделы, кнопки, пояснения, формы и служебные подписи. Названия позиций меню оставляются на английском по согласованному правилу. Переключатель языка находится слева в шапке.

Базовый текст интерфейса обычно записан по-русски. В dist/i18n.js словарь copy связывает его с польским и английским. Если меняется исходная фраза, нужно обновить и ключ перевода. При новом описании блюда добавьте соответствующий перевод; английское name не превращайте в локализованные варианты.

"Закуски": { pl: "Przystawki", en: "Starters" }

Проверка языка: /menu.html?lang=ru, /menu.html?lang=pl и /menu.html?lang=en. Для главной используйте те же параметры у index.html. Язык также запоминается в браузере. Сообщения состояния формы бронирования имеют отдельный словарь bookingCopy в dist/booking.js.

Сохраняйте действующий логотип, векторные стрелки и мобильную адаптацию. Анимация первого экрана связана со скроллом в app.js; изменения её размеров и фиксации могут вернуть рывки при смене направления прокрутки. Такие правки проверяются отдельно, включая первый свайп на телефоне.


7 Публикация через GitHub

Рабочая схема: задача в Claude → отдельная ветка → pull request → проверка → объединение с main → автоматическая загрузка на home.pl. Pull request, или PR, — это страница предлагаемых изменений перед включением в рабочую версию.

1. Начните новую задачу от актуальной main. Если одновременно работает Рома, предупредите Claude об этом: перед изменениями он должен проверить новые коммиты и существующие правки.
2. Опишите задачу и приложите материалы. Claude меняет файлы в рабочей ветке и проверяет результат. Для новой задачи удобнее отдельная небольшая правка, чем сразу переделка всего сайта.
3. Попросите выполнить npm run prepare:site, затем npm run check. Первая команда обновляет версии CSS и JS, вторая проверяет данные меню, синтаксис и пути к медиа.
4. Попросите Claude сохранить изменения, отправить ветку и создать PR в Svip-web/angels-warsaw-site с базой main. Если действие недоступно его инструментам, он должен дать ссылку на сравнение веток и помочь вам создать PR.
5. Откройте PR. Проверьте перечень изменений, цены и фотографии. Дождитесь успешного Check Angel's site. Просмотр файлов в PR не заменяет проверку внешнего вида.
6. Когда результат устраивает и вы хотите опубликовать, нажмите Merge pull request и подтверждение объединения, если кнопки доступны. При конфликте попросите Claude обновить ветку и разрешить его с сохранением чужих изменений.
7. Откройте вкладку Actions и запуск Publish Angel's site to home.pl для нового коммита main. Дождитесь статуса success. Если запуск queued или in progress, публикация ещё продолжается; failure означает ошибку.
8. Откройте основной сайт и проверьте конкретную правку. Попросите Claude подтвердить адрес страницы и результат. Успешный коммит или созданный PR ещё не означают, что сайт обновился.

8 Проверка результата и восстановление

Что должен проверить Claude

• Данные: точные названия, разделы, согласованные цены, единицы и варианты порций. После удаления позиции проверьте, что не осталось её дубликата.
• Медиа: фото соответствует товару, файл загружается, кадр не обрезает главный объект. Видео воспроизводится, имеет правильный постер, повторяется и не включает звук.
• Мобильное меню: ширины 360 и 390 px, две карточки в ряд, читаемые цены, отсутствие наездов на логотип и горизонтального выезда страницы. Отдельно проверьте 768 и 1440 px.
• Языки: RU, PL и EN; длинные подписи, кнопки, названия разделов и форма бронирования. Названия товаров остаются на английском.
• Навигация: вкладки Бар, Кухня и Кальяны, выделение активной вкладки, закреплённые категории и быстрый переход между ними.
• После публикации: успешный запуск именно для нужного коммита main и актуальные файлы на angelskaraoke.pl. Укажите, что проверено автоматически, а что просмотрено глазами.

npm run check проверяет структуру данных, неотрицательные числовые цены, JavaScript и наличие файлов. Он не знает утверждённых клиентом цен и не распознаёт, какое блюдо на фото. Эти соответствия нужно сверять отдельно. Просмотр на компьютере с мобильной шириной не заменяет проверку реального телефона, особенно для скролла и автовоспроизведения.

Как вернуть рабочую версию

Сначала зафиксируйте, что сломалось и после какого PR. Попросите Claude отменить конкретную правку отдельным коммитом или PR через revert, сохранив историю и более поздние полезные изменения. После объединения возврата с main снова дождитесь публикации и проверьте сайт. Не применяйте reset или force push к общей main для обычного отката.

Пример запроса: «После последней правки сломалось [описание]. Найди связанный PR, покажи причину и подготовь безопасный откат только этой правки. После моего указания опубликуй и проверь основной сайт».


9 Помощь при затруднениях

Claude не видит репозиторий

Проверьте, что в GitHub выполнен вход под anasteysha050307, а в Claude подключён этот же GitHub. Откройте репозиторий напрямую. Затем обновите выбор репозитория в Claude. Если появляется запрос владельцу на доступ приложения, передайте его Роме; не создавайте новый репозиторий вместо действующего.

Открыт обычный чат Claude

Обычный чат может помочь с инструкциями и подготовить файлы, но это само по себе не публикует сайт. Для работы с репозиторием откройте Claude Code. Если остаётесь в обычном чате, изменения нужно отдельно внести в проект, проверить и опубликовать через GitHub. Claude должен явно объяснить, какой режим сейчас доступен.

Правка сделана но сайт не изменился

Проверьте, объединён ли PR с main, есть ли успешный запуск home.pl и открыт ли правильный домен. Затем обновите страницу или проверьте приватное окно. Если устарел конкретный ролик или снимок, нужен новый адрес медиафайла. Не меняйте DNS для исправления обычного браузерного кеша.

Не приходит заявка в Telegram

Форма обращается к отдельному серверному API, который пересылает заявки в Telegram. Файл booking.js содержит клиентскую часть, а бот-токен и настройки доставки хранятся на сервере. Попросите Claude проверить сетевой ответ и валидацию формы. Изменение серверного API требует отдельного доступа; один доступ к этому GitHub его не предоставляет. Тестовую заявку отправляйте по явной просьбе и с понятной пометкой ТЕСТ.

Нужно изменить домен или сертификат

Основной рабочий адрес — https://angelskaraoke.pl/. Проблема сертификата старого .com отдельно отмечена в HOSTING-STATUS.md; не считайте её автоматически исправленной после обновления меню. Настройки доменов, почты, SSL и Telegram не входят в обычную правку контента и требуют отдельной задачи владельцу инфраструктуры.

Чего Claude не должен утверждать

Доступ к GitHub не даёт Claude историю Telegram, личные чаты Ромы, оригиналы на его диске или доступ к домашнему компьютеру клиентки. Для новой фотографии прикрепите файл или дайте доступный источник. Если инструмента публикации, браузера или API нет, Claude должен помочь выполнить недостающий шаг и честно назвать ограничение.

Не размещайте пароли, токены бота, личные данные заявок или FTP-доступ в dist, PR и публичных документах. Не подключайте стороннюю CAPTCHA или другой сервис для формы без отдельного решения владельца. Существующая доставка заявок должна продолжать работать через Telegram.


10 Примеры запросов для ежедневной работы

Добавить позицию

«Прочитай инструкции проекта. Добавь в Кухню → Закуски позицию [название], цена [сумма] zł. Фото прикреплено, описание [текст или не нужно]. Название на сайте оставь на английском. Проверь две карточки в ряд, RU, PL и EN. Подготовь PR и помоги мне его проверить».

Изменить цену или убрать позицию

«Измени цену [точное название] с [старая сумма] на [новая сумма] zł для варианта [порция]. Остальные цены не меняй. Покажи карточку и подготовь PR». Для удаления: «Убери из продажи [точное название] в разделе [раздел]. Проверь, что похожие позиции сохранились».

Заменить фотографию

«Замени фото позиции [название] прикреплённым файлом. Сохрани исходник отдельно, подготовь WebP и кадр 5:4 с фокусом на блюде. Используй новое имя файла, проверь мобильную карточку и не меняй цену».

Обновить текст или событие

«В блоке [название или ссылка] замени текст на [текст]. Обнови польский и английский переводы, проверь длину кнопок и мобильные переносы. Если в тексте не хватает даты, времени или условий, сначала уточни их».

Опубликовать проверенную правку

«Этот результат подходит, опубликуй его на основном сайте. Проверь успешные проверки, помоги объединить PR с main, дождись Publish Angel's site to home.pl и проверь [конкретная позиция или блок] на angelskaraoke.pl. При ошибке объясни её и помоги исправить».

Начать работу в новом чате

«Подключись к Svip-web/angels-warsaw-site. Прочитай CLAUDE.md и CLAUDE-CLIENT-GUIDE-ru.txt из актуальной main. Помоги мне шаг за шагом. Сейчас нужно [задача]. Скажи, каких материалов не хватает, затем выполни и проверь правку».
