# Подключение Claude, GitHub и home.pl

Текущее подключение и восстановление старого сайта описаны в
`HOSTING-STATUS.md`. Основной адрес нового сайта — https://angelskaraoke.pl/.

Локальная подготовка выполнена. Для включения публикации нужно
подключить аккаунт клиента и заполнить параметры хостинга.

## Что настроено в проекте

- `CLAUDE.md` описывает меню, цены, переводы и правила редактирования.
- `.claude/launch.json` запускает встроенный просмотр через `npm start`.
- `npm run check` проверяет синтаксис JavaScript, позиции меню, цены,
  ключи разделов, пути к изображениям и постеры видео.
- `npm run prepare:site` обновляет адреса CSS и JavaScript по содержимому файлов.
- `npm run package` создаёт проверенные ZIP с сайтом и проектом для Claude.
- `.github/workflows/check-site.yml` запускает проверку в GitHub.
- `.github/workflows/deploy-homepl.yml` содержит публикацию на home.pl.

Проверка файлов дополняется просмотром RU, PL и EN на телефоне и компьютере.
Новые позиции нужно проверить по подтверждённым названиям, ценам и фотографиям.

## Что потребуется от клиента

1. Аккаунт Claude с доступом к Claude Code.
2. GitHub-логин клиента, которому владелец предоставит доступ к репозиторию.
3. Подключение репозитория в Claude Code через собственный аккаунт клиента.

Для локальной работы можно открыть распакованный проект в Claude Code
и запустить просмотр из конфигурации Angels local preview.
Для браузерной работы клиент подключает GitHub на https://claude.ai/code.
Изменения из Claude сначала появляются в отдельной ветке.
После просмотра их объединяют с `main`.

## Однократное подключение home.pl

Перед первым запуском определите в панели home.pl каталог домена.
Для новой версии выберите отдельный каталог Angels и сохраните копию
старого сайта. У FTP-пользователя должен быть доступ к выбранному каталогу.

В GitHub откройте Settings → Environments и создайте окружение `homepl`.
В нём добавьте следующие переменные

| Variable | Значение |
| --- | --- |
| `HOMEPL_HOST` | `serwer2389562.home.pl` |
| `HOMEPL_DIRECTORY` | `./` для ограниченного FTP-пользователя `github-deploy@angelskaraoke.com` |
| `HOMEPL_PORT` | Порт explicit FTPS, обычно `21` |

FTP-пользователь ограничен каталогом `/angels-site`, который соответствует
`/public_html/angels-site` в WebFTP. Поэтому для этого пользователя загружайте
файлы в `./`, без повторения полного пути. Для другого FTP-пользователя путь
нужно проверить отдельно.

В Environment secrets добавьте

| Secret | Содержимое |
| --- | --- |
| `HOMEPL_FTP_USERNAME` | Имя FTP-пользователя |
| `HOMEPL_FTP_PASSWORD` | Его пароль |

Для активации создайте переменную репозитория
`HOMEPL_PUBLISH_ENABLED` со значением `true` в
Settings → Secrets and variables → Actions → Variables.
Первый запуск выполните вручную в Actions → Publish Angel's site to home.pl
с включённым `dry_run`. Он покажет план синхронизации.
Проверьте каталог и список изменений, затем запустите загрузку с выключенным
`dry_run`. Проверьте новую версию на временном адресе.

После перехода основного домена на этот каталог изменения `dist`
в ветке `main` будут автоматически загружаться на home.pl.
Этот переход также требует проверки HTTPS, разрешения origin домена
в API бронирования и проверки получения заявки в Telegram.
До подключения публикации на home.pl на репозитории сохраняется существующий
сценарий GitHub Pages. Его дальнейшее использование определяет владелец.

## Проверка и восстановление

Сценарий проверяет файлы перед отправкой. FTPS использует проверку
сертификата сервера. Загрузки выполняются последовательно, чтобы два запуска
GitHub Actions не синхронизировали один каталог одновременно.
Файл `.angels-ftp-sync.json` хранит состояние синхронизации.
Следующие загрузки учитывают изменения и удаление позиций из текущих файлов.

Обновление нескольких файлов через FTP происходит последовательно.
При обрыве загрузки повторите запуск того же коммита и проверьте сайт.
Для возврата к предыдущей версии отмените ошибочный коммит в GitHub
и запустите публикацию исправленной ветки `main`.
Для первого перехода со старого сайта используйте сохранённую резервную копию.
