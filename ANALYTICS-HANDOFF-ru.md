# Angel's — передача аналитики команде Blammo

Основной сайт: https://angelskaraoke.pl/ и https://angelskaraoke.pl/menu.html.
Обе страницы используют общий `dist/analytics.js` и общий `dist/booking.js`.
Языки: PL, EN, UK, RU. Верстка и существующие стили сайта не менялись.

## Идентификаторы из ТЗ

- GTM: `GTM-5Z32PTTB`.
- GA4: `G-N7Y80KC10T`, только через этот GTM, без второй установки gtag.js.
- Meta Pixel: `1583813716406623`, только из кода сайта, не дублировать в GTM.

## Статус интеграции сайта

На сайте подготовлены баннер, управление согласием и все пять событий.
Meta загружается только после согласия на маркетинг. Без согласия нет
скрипта Meta, изображения noscript и событий. Код автоматического сопоставления
контактных данных не добавлялся; автоматическая конфигурация Pixel отключена.

**GTM активен на стороне сайта: `const GOOGLE_READY = true`.**
Он загружается сразу при открытии обеих страниц на всех языках с исходным
согласием denied (Advanced Consent Mode v2). Пять явных сигналов отправляются
в Data Layer после согласия на аналитику. Дополнительной активации кода
сайта после настройки тегов не требуется. Сайт передает безопасные URL и
фиксированный заголовок перед загрузкой контейнера; значения полей не передаются.

Настройка тегов внутри GTM и приемка в кабинетах — отдельная сторона интеграции,
которую команда выполняет самостоятельно. Сайт не меняет удаленные настройки.
При чтении публичной опубликованной версии контейнера 26.11.2026 обнаружены:

- автоматическое отслеживание форм;
- дополнительные просмотры при изменении history;
- автоматический сбор email, телефона и адреса (user-provided data).

Автоматический сбор контактных данных нужно выключить в кабинете согласно ТЗ.
Автоматические события формы и history также нужно проверить на дублирование.
Это настройки опубликованного контейнера, а не источники событий в коде сайта.

## Что нужно настроить Blammo

1. В Google tag / GA4 выключить автоматический сбор user-provided data
   (email, телефон, адрес), включая связанные настройки тега.
2. В GA4 Enhanced Measurement выключить Form interactions и просмотры по
   browser history. У сайта модальная форма и навигационные якоря, это не
   новые страницы. Проверить, что в GTM нет второго автоматического form_start,
   триггеров Form Submission, Click или Element Visibility, создающих Lead.
3. Для управляемого согласия использовать Consent Initialization — All Pages
   и шаблон с `setDefaultConsentState` / `updateConsentState`. Исходник для
   вкладки Code находится в `analytics/gtm-consent-template.js`. Разрешения
   sandbox-шаблона: `access_consent` (read/write четырех типов ниже),
   `access_globals` (execute `ANGELS_ANALYTICS.getGoogleConsent` и
   `ANGELS_ANALYTICS.onConsentChange`).
   При создании шаблона проверьте запрошенные разрешения в интерфейсе GTM.
4. Сохранить один Google tag для `G-N7Y80KC10T`. Отключить у него автоматический
   `send_page_view` (false). Использовать этот Google tag как Setup tag в
   Tag Sequencing пяти тегов GA4, с Tag firing options = Once per page.
   Не оставлять параллельный запуск старой конфигурации на All Pages.
   Это также дает переменным безопасного URL значения из события до конфигурации.
   Не создавать
   еще один ресурс GA4 или контейнер GTM. Google tag запускается только с
   `analytics_storage = granted` для явных событий из таблицы.
   Сам GTM загружается сразу с denied defaults. В этом режиме встроенные
   Google tags могут отправлять cookieless pings; запись необязательных
   cookies разрешается после согласия. Meta до согласия не загружается.
5. Создать пять Custom Event triggers и пять GA4 Event tags из таблицы.
   Для всех GA4 tags требуется `analytics_storage`. Не использовать
   широкие regex-триггеры, захватывающие эти события второй раз.
6. Передавать параметры через Data Layer Variables v2 с именами из раздела
   ниже. Задать безопасные `page_location`, `page_referrer`, `page_title`
   и в Google tag; не подставлять полный URL с произвольным query/hash.
   Проверить, что отключенные автоматические события не отправляют URL отдельно.
7. Опубликовать согласованные изменения контейнера и проверить события.
   На стороне сайта ничего дополнительно включать или публиковать не нужно.
8. В Meta Events Manager проверить и выключить Automatic Advanced Matching
   и автоматические события/правила, если они включены для этого Pixel.
   Все согласованные события уже отправляет код сайта. Проверить, что
   данные формы не собираются скрытой автоматической настройкой кабинета.

## События

| Custom Event в Data Layer | GA4 Event name | Meta | Условие |
| --- | --- | --- | --- |
| `angels_page_view` | `page_view` | `PageView` (standard) | Один раз на документ после согласия |
| `angels_view_menu` | `view_menu` | `ViewMenu` (custom) | Открыта страница menu.html, один раз на документ |
| `angels_booking_click` | `booking_click` | `BookingClick` (custom) | Нажатие любой ссылки открытия бронирования |
| `angels_form_start` | `form_start` | `FormStart` (custom) | Первое focus/input/change поля формы; повторные поля не дублируют событие |
| `angels_generate_lead` | `generate_lead` | `Lead` (standard) | Только успешный HTTP-ответ API с `ok: true`, не honeypot |

Meta события уже отправляются кодом сайта. Не добавлять их копии через GTM.
GA4 события передаются исключительно через указанные Custom Event triggers.
Сайт не выполняет прямые вызовы GA4 `gtag('event', ...)`.

Параметры Data Layer: `page_type` (home/menu), `language` (ru/pl/en/uk),
`form_id` (booking), `form_location` (home/menu), безопасные `page_location`,
`page_referrer`, фиксированный `page_title`.
Имя, телефон, комментарий, дата, время, число гостей и значения полей
не включаются. Meta получает только `page_type`, `language`, `form_id`.
Для Meta разрешены только известные параметры URL (lang, v, fbclid, gclid,
utm_source/medium/campaign/content/term/id) ограниченного формата. При
произвольном query или hash Pixel не загружается/новые события не отправляются.
Не помещайте персональные данные в кампании, URL, заголовки и параметры рекламы.

## Согласие и отзыв

Все четыре параметра Google Consent Mode v2 изначально `denied`:
`analytics_storage`, `ad_storage`, `ad_user_data`, `ad_personalization`.
Выбор аналитики управляет первым; выбор маркетинга — остальными и Meta.
Нет предустановленных необязательных галочек. Кнопки «Принять все» и
«Только необходимые» доступны сразу. Отказ не мешает бронированию.
Выбор хранится локально 180 дней. Ссылка «Настройки cookies» находится в подвале.
При отзыве выбор сохраняется, cookies соответствующего поставщика удаляются,
Meta получает revoke, страница перезагружается для удаления уже загруженных
обработчиков. Изменение согласия в другой вкладке также обновляет страницу.

## Проверка Blammo в кабинетах

На обеих страницах, на телефоне и компьютере, на всех четырех языках:

1. Новый посетитель: GTM загружен сразу, четыре исходных статуса denied
   установлены до загрузки. До согласия нет необязательных cookies,
   явных событий из таблицы и запросов Meta. Cookieless pings Google допустимы.
   Форма доступна при отказе.
2. Только аналитика: явные события Google, без Meta. Только маркетинг:
   Meta активен, Google остается с analytics_storage = denied.
3. Согласие на все: один PageView/page_view и ViewMenu/view_menu в меню.
   Изменение якоря и открытие/закрытие формы не создают новый просмотр.
4. Клик бронирования — BookingClick/booking_click, а не Lead.
5. Несколько взаимодействий с одной формой — один FormStart/form_start.
6. Пустая/некорректная форма, HTTP 400/422/429/500/502, потеря сети — нет Lead.
7. Успешная заявка — ровно один Lead и один generate_lead. Проверить все
   обязательные поля и доставку в Telegram. Согласовать тестовую заявку
   с владельцем; при разработке использовались только локальные ответы-заглушки.
8. Повторное открытие подтверждения, обновление, повторный Enter во время
   отправки — не создают новую конверсию. Новая успешно отправленная заявка
   после завершения первой учитывается отдельно.
9. Нет согласия в момент успешной заявки — нет ретроспективной конверсии
   после более позднего согласия.
10. Отзыв согласия, перезагрузка и новая вкладка: отказ сохранен; GTM загружен
    с denied, необязательные cookies/явные события выключены, Meta не грузится.

Подтверждение: GTM Preview/Tag Assistant, GA4 DebugView и Realtime, Meta Test
Events и Diagnostics. Проверить фактические сетевые payload, отсутствие PII
и дублирования. `generate_lead` отметить key event после согласования команды.
Сайт не включает debug_mode на всем рабочем трафике.

При блокировщике рекламы или отсутствии согласия доставка аналитики не
гарантируется; бронь продолжает работать. Отключенный JavaScript не запускает
Pixel через noscript: согласие в таком случае получить нельзя.

Файлы: `dist/analytics.js`, `dist/consent.css`, подключение в двух HTML,
один вызов в подтвержденной ветке `dist/booking.js`. Остальные стили,
контент, переводы, медиа, API и Telegram-настройки не изменены.
